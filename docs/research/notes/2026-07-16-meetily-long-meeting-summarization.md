# Meetily long-meeting summarization (official implementation)

Date: 2026-07-16
Source baseline: Meetily `main` at [`0281737d87d26352fb0adc78c8c0975f691b23d1`](https://github.com/Zackriya-Solutions/meetily/tree/0281737d87d26352fb0adc78c8c0975f691b23d1). This note uses only the official repository. Observations labelled “implication” are deductions from the cited code, not maintainer claims.

## What Meetily actually does

- **Implementation location.** The desktop UI fetches every transcript segment, adds timestamps, and submits one joined transcript. The Rust summary service selects the context threshold and calls the processor; `processor.rs` implements the summarization pipeline; `llm_client.rs` implements provider calls. ([UI payload](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src/hooks/meeting-details/useSummaryGeneration.ts#L401-L475), [service threshold selection](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/service.rs#L393-L437), [processor entry point](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L297-L343))

- **Local and remote paths.** Supported paths are Ollama through its OpenAI-compatible `/v1/chat/completions`, a built-in local GGUF sidecar, OpenAI, Claude, Groq, OpenRouter, and a custom OpenAI-compatible endpoint. Ollama defaults to `http://localhost:11434`. ([provider routing](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/llm_client.rs#L66-L89), [local/remote dispatch](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/llm_client.rs#L128-L201))

- **Short/cloud strategy: one shot, then formatting.** All non-local providers are treated as having an effective 100,000-token threshold, and all transcripts below the selected threshold go directly to a final template-filling call. Thus the base English result is one LLM call, not one call per output product. ([threshold policy](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/service.rs#L393-L437), [single-pass branch and final report](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L354-L376))

- **Long-local strategy: shallow map/combine/final, not recursive reduce or refine.** For Ollama or built-in AI over the threshold, Meetily splits the transcript into overlapping chunks, summarizes each chunk sequentially, concatenates all chunk summaries, performs exactly one combine call, and then performs one final template-filling call. It does not recursively reduce until a size/contraction condition is met, and it does not maintain a rolling/refine state. ([chunk map loop](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L366-L445), [single combine and final pass](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L446-L523))

- **Chunking and context accounting.** Token count is estimated as `ceil(chars × 0.35)`. Chunking converts that estimate back to characters, uses a 100-token overlap, and prefers a sentence or word boundary. Ollama’s threshold is model metadata context size minus 300; the processor then chunks at `threshold - 300`, effectively reserving another 300 tokens. Metadata failure falls back to a 4,000-token threshold. Built-in models currently declare 32,768-token contexts. ([estimator/chunker](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L176-L252), [thresholds and fallbacks](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/service.rs#L393-L437), [built-in model contexts](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/summary_engine/models.rs#L162-L218))

- **Call-count and runtime controls.** With `n` long-local chunks, the base English pipeline makes `n + 2` serial model calls (`n` maps + one combine + one final report); with one chunk it makes two. Translation or soft English normalization may add one more call. Every HTTP LLM request has a 300-second timeout and can be cancelled by the user; cancellation is checked between chunks. There is no whole-run call budget, wall-clock deadline, reduction-depth limit, or parallel chunk execution in this pipeline. Failed chunk calls are skipped unless every chunk fails. ([serial map and partial-failure behavior](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L387-L445), [combine/final calls](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L446-L523), [per-request timeout/cancellation](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/llm_client.rs#L1-L8), [request race](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/llm_client.rs#L256-L290), [stop action](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src/hooks/meeting-details/useSummaryGeneration.ts#L635-L655))

- **Output products.** Meetily generates one templated Markdown report rather than independently mapping/reducing timeline, actions, and general summary. The standard template contains Summary, Key Decisions, Action Items (owner/task/due/reference/timestamp), and Discussion Highlights; a standup template has Date, Attendees, Yesterday, Today, Blockers, and Notes. Custom templates determine the sections. ([standard template](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/templates/standard_meeting.json), [standup template](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/templates/daily_standup.json), [template-driven final prompt](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L476-L518))

## Explicit/structural long-transcript limitations

The inspected official source does not publish a maximum meeting duration or transcript-length guarantee. It does expose these structural limits:

1. **The combined summaries are not re-chunked before the combine call.** Therefore a sufficiently large number of chunk summaries can itself exceed the local model context. This is an implication of joining every map result and sending the joined string in one request. ([combine implementation](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L446-L470))
2. **The final report is also one call.** Its input is either the full transcript (single-pass path) or the one combined summary; it has no second size check. ([final report implementation](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L476-L518))
3. **Cloud/custom providers bypass long-input chunking.** The source labels them “effectively unlimited” at 100,000 estimated tokens, so provider-specific context limits below that value are not enforced locally. ([service policy](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/service.rs#L434-L437), [branch condition](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L366-L376))
4. **Runtime grows linearly with chunk count.** The map calls are awaited one after another and the only automatic time bound is per request, not per meeting. ([serial loop](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/processor.rs#L390-L431), [request timeout](https://github.com/Zackriya-Solutions/meetily/blob/0281737d87d26352fb0adc78c8c0975f691b23d1/frontend/src-tauri/src/summary/llm_client.rs#L256-L290))

## Comparison takeaway for the next experiment

Meetily’s relevant simplification is architectural: **one summary artifact, one map pass, one combine pass, one final formatting pass**. It avoids a recursive, source-rehydrating reduction graph and therefore has a predictable call formula. It does **not** solve arbitrarily long transcripts robustly: it lacks a whole-run budget and a bounded hierarchical combine. The useful pattern to test next is its shallow pipeline and unified template output, while adding safeguards Meetily itself lacks: a strict whole-run deadline/call cap and a deterministic size check (or bounded multi-level combine) before every model call.
